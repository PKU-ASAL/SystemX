# SysArmor v2 Endpoint Runtime Changelog

Date: 2026-06-15

## Summary

v2 turns the v1 detection path into a long-running EDR endpoint runtime MVP. The core change is that `sysarmor-agent` is no longer only a replay/stream uploader: it can run as a daemon, own a sensor runtime, apply collection policy, buffer uploads locally, retry safely, report health, and recover from sensor or manager failures.

Primary path:

```text
sysarmor-agent run --config ...
  -> load runtime scope and identity
  -> probe / start / supervise sensor runtime
  -> apply collection policy
  -> subscribe Tetragon events
  -> normalize + endpoint fastpath
  -> write durable spool batches
  -> upload with retry / ack / idempotency
  -> report health and tamper/blindness signals
  -> sysarmor-manager / sysarmorctl health and detection queries
```

v2 also fixes the container architecture direction. Containers are treated as workload scopes, not as miniature VMs. The default container deployment model is an independent privileged `sysarmor-agent + tetragon` sensor container observing a target workload scope.

## Added

### Agent Daemon Runtime

- Added `sysarmor-agent run --config ...` daemon mode.
- Added config loading and `--dry-run` validation.
- Added daemon pipeline for:
  - sensor runtime initialization
  - policy apply
  - event normalize / fastpath
  - spool writes
  - data batch drain / retry loop
  - health reporting
  - graceful shutdown drain
- Kept v1 replay and stream paths for compatibility and debugging.

### Sensor Runtime Contract

- Added `internal/sensor/runtime`.
- Added sensor interface boundaries for:

## Compatibility

- v1 replay and stream modes remain available.
- v1 detection behavior remains the baseline for attack scenario semantics.
- `container_id_prefix` remains supported as a legacy alias, but the product contract is now `sensor.scope.type + sensor.scope.selector`.
- Tetragon remains the first Linux sensor backend, not the product boundary.

## Known Limits

- v2 is an EDR endpoint runtime MVP, not a full EDR product.
- `Enforce` is still observe-only / unsupported skeleton, not production blocking.
- Native sensor is not implemented.
- Rule content is still mostly compiled Go logic, not a full content-pack system.
- Store is still file-backed MVP storage, not SQLite/Postgres.
- Production enrollment, mTLS, RBAC, and tenant administration are not included.
- Investigation UI, response orchestration, evidence pullback, and incident lifecycle are not included.
- XDR ingestion for cloud audit, identity, network, K8s audit, CI/CD, and registry events is not included.
- Longer soak windows and broader real-world permission matrices remain hardening work.
