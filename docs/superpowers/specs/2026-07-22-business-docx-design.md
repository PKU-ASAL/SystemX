# 中文公文式项目建议书 DOCX 设计规格

## 目标

为 `docs/business/sysarmor-project-proposal.zh-CN.md` 建立可重复、可验证的 DOCX 构建链，输出适合政府部门、中央企业和地方国有企业立项讨论及打印流转的正式交付件。

成品采用 GB/T 9704-2012 的版心、字体层级和页码习惯，同时保留技术项目建议书需要的中性封面、自动目录、图表、表格、代码命令和附录。成品不是红头文件，不包含发文机关标志、文号、签发人、印章或未经确认的编制单位。

## 输出与入口

- 构建入口：`make business-docx`
- Markdown 源文件：`docs/business/sysarmor-project-proposal.zh-CN.md`
- 输出文件：`dist/docs/sysarmor-project-proposal.zh-CN.docx`
- 中间文件：仅写入临时目录，构建结束后清理
- 构建产物：由现有 `dist/` 规则忽略，不提交 Git

构建失败必须说明缺少的命令及安装方向，不得静默跳过图片、样式或验证。

## 文档结构

### 中性封面

封面只包含以下信息：

1. `SysArmor 主机安全技术研究及平台建设项目建议书`
2. `面向政府与国有企业场景`
3. `项目建议书（讨论稿）`
4. `二〇二六年七月`

封面不显示单位、Logo、密级、文号和页码。项目名称位于页面视觉中上部，材料类型与日期位于下部，整体居中，不使用色带、边框、水印或装饰图形。

### 目录

目录单独起页，标题为“目　录”，收录一级至三级标题。目录不显示页码；Word 或 WPS 打开文件时应能够更新目录域。

### 正文

正文从新节开始，页码重新从 1 计数。源文件中的重复一级项目名称不进入正文，正文从“编制说明”开始。章节顺序、内容和能力边界保持不变。

正文中的四张技术路线图按出现顺序编号。图题格式为：

```text
图 1　动态博弈通过统一策略控制平面形成受约束的持续调整闭环
```

表题置于表格上方，图题置于图片下方。题注使用连续阿拉伯数字，不跨章节重新编号。

## 页面规范

| 项目 | 规格 |
|---|---|
| 纸张 | A4，210 mm × 297 mm，纵向 |
| 上边距 | 37 mm |
| 下边距 | 35 mm |
| 左边距 | 28 mm |
| 右边距 | 26 mm |
| 页眉距离 | 15 mm |
| 页脚距离 | 17.5 mm |
| 正文版心 | 约 156 mm × 225 mm |
| 文档网格 | 每页约 22 行、每行约 28 个三号汉字 |
| 页码 | 页脚居中，格式 `— 1 —` |

封面和目录属于前置部分，不使用正文页脚。正文节的页码从 1 开始。

## 字体与段落

字体在 DOCX 中使用中文公文字体名称声明；构建机没有对应商业字体时允许 LibreOffice 使用本地中文字体回退，但不得因此改变模板声明。

| 内容 | 中文字体 | 字号 | 段落规则 |
|---|---|---|---|
| 封面项目名称 | 方正小标宋简体 | 二号，22 pt | 居中，单倍行距 |
| 封面副标题 | 楷体_GB2312 | 三号，16 pt | 居中 |
| 材料类型 | 方正小标宋简体 | 三号，16 pt | 居中 |
| 封面日期 | 仿宋_GB2312 | 三号，16 pt | 居中 |
| 目录标题 | 方正小标宋简体 | 二号，22 pt | 居中 |
| 一级标题 | 黑体 | 三号，16 pt | 不缩进，段前段后适度留白 |
| 二级标题 | 楷体_GB2312 | 三号，16 pt | 不缩进，加粗 |
| 三级、四级标题 | 仿宋_GB2312 | 三号，16 pt | 不缩进，加粗 |
| 正文 | 仿宋_GB2312 | 三号，16 pt | 首行缩进 2 字符，固定值约 29 pt |
| 表格正文 | 宋体 | 五号，10.5 pt | 单倍行距，垂直居中 |
| 图题、表题 | 宋体 | 五号，10.5 pt | 居中，题注与对象不跨页 |
| 代码和命令 | 等宽字体 | 小五，9 pt | 不缩进，浅灰底 |
| 拉丁字母与数字 | Times New Roman | 随所在样式 | 不单独改变字号 |

列表和表格单元格不继承正文首行缩进。孤行控制、标题与下段同页、表格表头重复和表格行禁止跨页作为默认排版约束。

## 图表策略

### 技术路线图

构建时将四张 SVG 转为高分辨率 PNG，再由 Pandoc 嵌入 DOCX：

- 横向专题图：输出宽度 2400 px，在文档中显示宽度 15.4 cm；
- 纵向总体图：输出宽度 2400 px，在文档中显示宽度 12 cm；
- 保持宽高比，不裁剪，不拉伸；
- PNG 仅作为构建中间文件，不提交仓库；
- SVG 与 Draw.io 继续作为正式源资产。

采用 PNG 是为了兼容旧版 Microsoft Office 和 WPS。DOCX 中必须实际包含四张非空图片，不能保留外部文件链接。

### 表格

表格使用黑色细边框和白色背景，不使用彩色表头。表头加粗、水平和垂直居中；正文根据内容左对齐或居中。宽表优先调整列宽和表内字号，不自动切换横向页面。

Markdown 中已有的五张核心表增加明确表题：现有方案能力边界、当前能力边界、实施计划、考核指标、业务概念与工程名称对照。其余短表如进入正式交付件，同样按出现顺序编号。

## 构建架构

### Makefile

根 `Makefile` 新增 `business-docx` 目标和帮助文本。目标只负责调用文档构建脚本，不在 Makefile 中堆叠 OpenXML 处理逻辑。

### 构建脚本

新增 `tools/docs/build-business-docx.sh`，职责如下：

1. 检查 `pandoc`、`python3`、`ffmpeg`、`zip`、`unzip`、`xmllint`、LibreOffice 和 `python3-uno`；
2. 创建临时工作目录和 `dist/docs/`；
3. 将四张 SVG 转为 2400 px 宽 PNG；
4. 使用仓库内已审查的中文公文式 reference DOCX；
5. 使用 Lua 过滤器处理重复标题、前置部分分节、图片尺寸和图题样式；
6. 使用 Markdown reader 编译，确保 YAML 元数据不进入正文；
7. 验证输出 DOCX 的结构、页面、字体、图片和页码；
8. 成功后原子地替换正式输出文件。

脚本在任何必需步骤失败时返回非零状态，并保留足以定位问题的错误说明。

### OpenXML 模板生成器

新增仅使用 Python 标准库的 `tools/docs/business_docx.py`。它从 Pandoc 默认 reference DOCX 生成并维护仓库模板，结构化修改：

- `word/styles.xml`：中文字体、字号、段落、目录、表格和题注样式；
- `word/document.xml`：A4 页面、页边距、文档网格和正文页码起始值；
- `word/footer1.xml`：居中的 `— PAGE —` 动态页码；
- 关系和内容类型文件：登记页脚；
- `word/settings.xml`：打开文档时更新目录和页码域。

生成器不依赖 `python-docx`，避免为单一构建任务引入运行时包依赖。

### Pandoc Lua 过滤器

新增 `tools/docs/business_docx.lua`，只处理 Pandoc 抽象语法树中的文档语义：

- 删除与元数据标题重复的第一个一级标题；
- 在正文开始前插入前置部分到正文的分节符；
- 将四张 SVG 引用替换为临时 PNG，并设置固定显示宽度；
- 将“图：”段落转换为连续编号的 Caption 样式；
- 保持链接、表格、列表和代码块语义不变。

不使用正则表达式直接改写整个 Markdown 文本。

## 依赖与兼容性

必需依赖：

- Pandoc 2.9 或更高版本；
- Python 3；OpenXML 处理仅使用标准库；
- FFmpeg，必须启用 SVG/librsvg 输入；
- zip、unzip、xmllint。
- LibreOffice Writer 和 `python3-uno`，用于生成并保存非空中文目录。

LibreOffice 是生成已填充中文目录的必需依赖，也用于本地验收时将 DOCX 转为 PDF。成品以 Microsoft Word 和 WPS 的 DOCX 兼容性为优先目标。

## 验收标准

### 自动检查

1. `make business-docx` 在干净工作区成功生成 DOCX。
2. 文件类型识别为 Microsoft OOXML/Word 文档，大小非零。
3. DOCX ZIP 内包含四张 PNG，且每张大小非零。
4. `word/document.xml` 声明 A4 页面、规定页边距、正文页码从 1 开始。
5. `word/styles.xml` 包含方正小标宋简体、仿宋_GB2312、黑体、楷体_GB2312、宋体和 Times New Roman 声明。
6. 页脚 XML 包含动态 PAGE 域和两侧破折号。
7. 文档正文不出现 YAML 键名、英文 `Table of Contents` 或重复项目名称标题。
8. 文档包含“目　录”、四个连续图号和五个核心表号。
9. 所有中间 PNG、DOCX 和 PDF 均不进入 Git；已审查的 reference DOCX 作为构建输入提交。

### 视觉检查

使用 LibreOffice 将成品转为 PDF并逐页检查：

- 纸张为 A4，封面、目录、正文分节正确；
- 封面无单位、Logo 和页码；
- 正文首页显示 `— 1 —`；
- 中文无乱码，标题层级清晰；
- 四张图完整、清晰、无裁切或不成比例缩放；
- 表格不超出版心，表头和题注不孤立；
- 总体技术路线图单独成页，图题与图片同页；
- 没有大面积异常空白、孤行或标题悬挂页尾。
