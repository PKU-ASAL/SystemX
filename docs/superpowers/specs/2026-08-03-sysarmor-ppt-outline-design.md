# SysArmor 五页 PPT 内容设计

## 目标

将 `docs/business/research/draft.md` 中 SysArmor 部分重写为面向技术专家和技术评审的五页 PPT 大纲。内容以技术问题、实现机制和验证证据为主，清楚区分当前能力、工程基础和规划能力。

## 表达原则

- 从安全防御的基本问题出发：看见行为、识别风险、关联证据、形成结论、执行响应、验证效果。
- 首次出现内部概念时使用通俗语言解释，再标注 Event、Signal、Evidence、Incident 等术语。
- 每页围绕一个核心结论组织，采用“难点、机制、效果与边界”的结构。
- 只陈述代码、架构文档或测试体系能够支持的当前能力；未实现能力明确标为规划。
- 保持 PPT 信息密度，不写成产品手册或代码说明书。

## 五页结构

### 第 1 页：定位与总体架构

核心结论：SysArmor 通过端侧自治与云侧关联，将分散的主机行为转化为可复核的安全事件，并为受控响应提供依据。

内容包括：

- Linux 主机安全面临的三个基本问题：行为数量大、单点行为语义弱、处置具有副作用。
- “行为采集 -> 可疑线索识别 -> 跨时间和实体关联 -> 安全事件形成 -> 受控响应”的技术链路。
- Endpoint Agent、Gateway、Worker、Manager 的职责边界。
- 当前阶段判断：安全分析链路已形成，真实阻断和 Agent 自主进化尚未形成完整闭环。

### 第 2 页：细粒度行为采集

核心结论：当前以 eBPF/Tetragon 为主要数据源，在内核可见性、采集成本和端点自治之间建立可控边界。

内容包括：

- 当前覆盖进程执行、派生和退出，文件打开、读取、写入和权限变更，以及网络连接。
- 采集上下文包括进程身份、父子关系、命令参数、UID、容器或 cgroup、文件路径、目标地址和端口。
- 采集条件优先下推到内核，剩余受支持条件由 Agent 过滤，不支持条件显式报告。
- Agent 支持离线采集、本地检测、有界存储、丢弃和错误可观测。
- Hypervisor 层采集作为后续数据源方向，不描述为当前能力。
- 性能数字必须来自固定环境下的 medium 或 long 性能测试，不在大纲中推算。

### 第 3 页：端云协同检测与图关联

核心结论：端侧快速提炼可疑线索，云侧利用更长时间窗口和实体关系判断多个线索是否属于同一攻击过程。

内容包括：

- 端侧表达式规则、多阶段 CEP、时间和顺序约束、实体一致性、进程 lineage、context 与 IOC。
- 云侧按 tenant、分析标签和 15 分钟窗口合并历史数据并稳定去重。
- 从进程、文件、网络实体构建 Evidence 子图，支持 K-hop 和最短路径。
- 用通俗语言解释 Event、Signal、Evidence、Incident 的递进关系。
- 明确当前图能力不等于完整因果路径恢复、攻击阶段推理或自然语言根因解释。
- KnowHow、NodLink 未在当前代码库落地，不作为当前实现表述。

### 第 4 页：受约束的自动化响应

核心结论：响应的首要问题不是让 Agent 自由执行，而是确保每个动作有授权、可追踪、可重试且不会重复造成副作用。

内容包括：

- 长程任务中的上下文漂移、重复执行、越权和失败恢复难题。
- 统一 Response Policy 对动作、模式、作用域、审批人数、审批角色和破坏性操作进行约束。
- Manager 持久化命令和审批，Gateway 下发，Agent 返回结构化回执，全程保留审计记录。
- 以持久化状态、幂等标识、前置条件、重试预算、超时、验证和补偿代替对模型对话上下文的依赖。
- 当前已验证响应编排链路；Tetragon 后端真实 enforce、隔离和阻断尚未产品化。

### 第 5 页：验证体系与演进路线

核心结论：SysArmor 以可重复测试界定能力，后续演进从补齐证据和可撤销响应开始，再进入 Agentic 优化。

内容包括：

- Functional、Detection、Performance 三类测试分别验证产品链路、检测效果和资源开销。
- Detection 使用恶意 required truth 和良性 forbidden detection；当前默认场景不等于 50 个漏洞环境。
- 性能测试覆盖 Agent、Sensor 和平台的 CPU、RSS、吞吐、丢弃、解析错误与阶段耗时。
- 当前评分器主要消费 Event 和 Signal，Incident 与 Evidence 尚未成为完整门禁。
- 演进顺序：扩大场景集 -> Incident/Evidence 门禁 -> 真实材料回拉 -> 可撤销响应 -> 受策略约束的 Agentic 调优。

## 验收标准

- SysArmor 部分明确分为五页，且每页只有一个核心结论。
- 技术专家无需预先理解内部数据模型即可读懂完整链路。
- eBPF 采集、端侧检测、云侧关联、图算法和响应编排均与当前实现一致。
- Hypervisor、KnowHow/NodLink、真实阻断和 Agent 自演化均未被误写为已实现。
- 未填写没有正式测试产物支持的性能、准确率或误报率数字。
- 不修改 Sysfield、Sysspear 或其他无关内容。
