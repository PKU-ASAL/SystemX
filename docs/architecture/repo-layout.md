# Repository Layout

SysArmor follows a Go service layout with EDR product assets separated from
implementation code.

## Source Code

```text
cmd/                 executable entrypoints
api/proto/           protobuf contracts
internal/            private Go implementation
```

Important internal domains:

```text
internal/agent/      endpoint agent runtime
internal/gateway/    agent-facing access layer
internal/manager/api operator-facing manager API
internal/workers/    background platform workers
internal/endpoint/   endpoint normalization, detection, upload clients
internal/sensors/    sensor contract and platform-specific adapters
internal/analytics/  cloud-side correlation, evidence, incidents
internal/platform/   Kafka/OpenSearch/Redis adapters
internal/store/      platform state store
```

Sensor adapters are platform-aware:

```text
internal/sensors/
  contract/
  fake/
  runtime/
  linux/
    tetragon/
  windows/           reserved
```

## Product Assets

```text
configs/             product default configs, policies, and content
deployments/         runtime deployment assets
packages/            product distribution package definitions
web/                 future operator UI projects
```

Boundary rules:

- `configs/` contains configuration and content sources.
- `deployments/` describes how services run.
- `packages/` describes how agent/sensor artifacts are built and distributed.
- `web/` is independent UI workspace territory.

## Tests And References

```text
test/                product, effectiveness, and performance suites
tools/               developer and operational helper tools
dist/                local generated build artifacts
```

`dist/` is regenerated by `make build` and ignored by git. Local scratchpads and
external research material should stay outside the product source tree or under
ignored local-only folders.
